逐家優缺點

依「架構」而非「功能清單」評判——優點聚焦可借鏡的設計決策，缺點聚焦結構性限制。

Claude Code Anthropic 專有 (source-available)
優點（架構上值得學）
  • ✓ harness 分層清晰：模型推理與工具行動解耦，skills/MCP/hooks/subagents 為可堆疊擴充層
  • ✓ context 經濟學到位：skill 按需載入、MCP schema 延後、subagent 獨立 context 只回摘要
  • ✓ 記憶分層明確：使用者寫的 CLAUDE.md 與 agent 自寫 auto memory 互補
  • ✓ 權限 × 沙箱雙軌：permission modes 兼顧便利與監督，沙箱內指令可免逐一批准
  • ✓ 可復原性：checkpoint（改檔前快照）＋ session resume/fork
缺點 / 限制
  • ✗ 閉源綁定商業模型：專有授權，主要面向 Claude 模型與 Anthropic 帳號生態
  • ✗ auto-compact 有損：早期對話細節壓縮後遺失，極端情況 thrashing 停手
  • ✗ 沙箱覆蓋不全：僅 shell 指令，檔案工具/MCP/hooks 不在內
  • ✗ 平台差異：原生 Windows 無沙箱、Grep/Glob 在部分平台預設缺席
  • ✗ 會收集使用資料與對話內容
Codex CLI OpenAI Apache-2.0 (開源)
優點（架構上值得學）
  • ✓ **沙箱與核准解耦成兩層**：沙箱定義技術邊界、核准定義何時問，低風險動作自動執行，大幅降 approval fatigue
  • ✓ 用 OS 原生機制而非僅工具層攔截，對子程序一體適用
  • ✓ 網路預設關閉、可寫根保護 .git/.codex、writable roots 可擴充仍保留沙箱
  • ✓ Linux 以 bubblewrap 取代 Landlock，解決 Unix socket 隔離的務實修正
  • ✓ 開源 Apache-2.0 + Rust，可用 Ollama/LM Studio 及自訂 provider 換非 OpenAI 模型
  • ✓ auto_review reviewer agent 與 subagent 對抗 context rot
缺點 / 限制
  • ✗ Linux 沙箱依賴 bubblewrap 與 unprivileged user namespace，舊發行版需 AppArmor 設定；WSL1 不支援
  • ✗ Landlock 路徑廢除但舊設定需手動關閉否則報錯
  • ✗ 網路 proxy 只涵蓋命令子程序，web search/MCP/browser 走獨立通道，安全邊界難一次講清
  • ✗ untrusted 核准政策移除造成遷移成本
  • ✗ subagent 與 auto_review 增加 token 消耗；本機與雲端沙箱語意不統一
  • ✗ AGENTS.md 合併上限 32 KiB、skill 清單 2% 預算，大型專案可能被截斷
DeepSeek Harness DeepSeek (dsh) MIT (開源)
優點（架構上值得學）
  • ✓ **狀態持久化提升為 runtime 不變量**：『Model-visible ⟺ logged』（官方明文：Every model request must be reconstructable from the log）——replay/fork/resume/telemetry/UI 全部免費繼承同一份 durable settlement
  • ✓ **零特權核心的插件化**：連 agent loop、session log、tool registry 都可替換；capability seam 讓換一個 provider 就換掉整個產品行為
  • ✓ Fail-closed 安全模型：approval 缺 answerer 即拒絕、sandbox partial 明確標示、能力不符即 typed error 拒絕而非靜默降級
  • ✓ 可重構的請求：request/header + context 皆入 log，請求成為 log 的純函數，除錯與審計性極佳
缺點 / 限制
  • ✗ **成熟度**：README 明言 developer preview，『THERE WILL BE COMPATIBILITY-BREAKING CHANGES』
  • ✗ **複雜度高**：事件驅動＋Cordis＋大量 branded types、migration chain、projection seam，學習曲線陡峭
  • ✗ 摘要壓縮固有風險：compaction 以 surface replace 覆蓋歷史，早期上下文僅存於 summary，資訊必然有損
  • ✗ Sandbox 非完整隔離：只管檔案效應，網路/行程可見性不在 policy 內；Windows/舊核心為 partial enforcement
  • ✗ 插件化代價：預設行為可能因 composition 而異，需 --dump-config 才能確認實際樹
Gemini CLI Google Apache-2.0 (開源)
優點（架構上值得學）
  • ✓ **開源 Apache-2.0 ＋ 免費層**（60/1000 配額）讓個人開發者零成本試用，是採用率關鍵
  • ✓ MCP 一等公民：三 transport、OAuth、trust、per-server include/exclude，並整合進 @ 參照與 tool registry
  • ✓ Hook 系統覆蓋完整生命週期（含 PreCompress），可做企業級策略/審計，且對 project hook 做 fingerprint 防 git pull 換毒
  • ✓ 漸進式揭露的 Skills 與獨立 context 的 subagents，有效控 token
  • ✓ Sandbox 選項極廣（Seatbelt/Docker/Podman/gVisor/LXC/Windows）＋ Sandbox Expansion 動態提權
  • ✓ Policy Engine 以宣告式 TOML 統一 allow/deny/ask，設計乾淨
缺點 / 限制
  • ✗ Checkpointing 預設關閉且啟動方式歷經變更（flag 被移除），使用門檻高
  • ✗ Sandbox 各平台行為不一致：browser agent 在 seatbelt 下被強制 headless、Docker 內被迫用 existing 模式接 host Chrome（port 9222 硬編碼）
  • ✗ LXC/gVisor 需顯式設定、LXC 容器需自行先建立；Windows 沙箱會永久改檔案完整性等級
  • ✗ Hook 極脆弱：stdout 任何非 JSON 輸出即失敗，且失敗時預設 Allow（fail-open），安全上偏寬鬆
  • ✗ 免費層配額不適用 Vertex/企業，pro→flash 自動降級對複雜任務品質影響大
  • ✗ Core 架構細節（loop 具體實作）官方文件未明確說明，需讀原始碼
Hermes Agent Nous Research (本機・對照) MIT (開源)
優點（架構上值得學）
  • ✓ provider-agnostic：20+ provider 可中途換模型、credential pool 自動輪替（不受單一商業模型綁定）
  • ✓ 多平台 gateway：同一 agent 在 15+ 訊息平台上跑，具完整工具存取
  • ✓ 四層持久化把『狀態別只留在 context window』制度化
  • ✓ profiles 隔離；cron / kanban / curator / webhook 等 durable 子系統齊備
  • ✓ 開源 MIT + Python 生態
缺點 / 限制
  • ✗ delegate_task 非持久：parent 中斷則 child 取消（需長任務得靠 cron/background）
  • ✗ toolsets 與 config 變更需 /reset 或 /restart 才生效（保 prompt caching 的取捨）
  • ✗ 相對資淺：生態與第三方整合深度不及 Claude Code / Codex
  • ✗ 無內建 OS 級 shell 沙箱（隔離靠 terminal backend 容器化或 worktree）

工程細節逐項對照

八個工程維度的逐家細節。所有結論均附官方來源（見下節）。

Claude Code Anthropic
核心 agentic loopgather context → take action → verify results，循環直到完成。單回合可鏈結數十個工具呼叫並中途修正。串流細節官方未以專章說明。
Context 管理auto-compact（先清舊工具輸出、再摘要整段對話）；可 /compact 指定重點；thrashing 時停手報錯。CLAUDE.md 四層載入（managed policy / user / project / local），另讀 AGENTS.md。MCP schema 預設延後載入。
權限 / 核准模型六種 permission modes：default / acceptEdits / plan / auto / dontAsk / bypassPermissions；settings 可疊加 allow/ask/deny。某些動作永不自動批准（明確 ask、AskUserQuestion、critical path 的 rm）。
Sandbox / 隔離有 OS 級沙箱（預設關閉）：macOS Seatbelt、Linux/WSL2 bubblewrap+socat（可選 seccomp），基於開源 @anthropic-ai/sandbox-runtime。⚠️ 只涵蓋 shell 指令——檔案工具、MCP、hooks 在沙箱外執行。原生 Windows 無沙箱（需 WSL2）。
Subagent 委派有 Agent 工具（Task 委派）：subagent 在獨立 context window、自訂 system prompt、限定工具與獨立權限，只回摘要。內建 Explore（唯讀）、Plan、general-purpose。可用 .claude/agents/ 自訂，支援 isolation: worktree。描述合計 >15k tokens 會警告。
Skills 機制SKILL.md（Agent Skills 開放標準 agentskills.io）。按需載入：session 開始只載一行描述（~450 tokens），用到才載全文。原 custom commands 已併入 skills。
狀態持久化每次對話存為 ~/.claude/projects/ 下純文字 JSONL；支援 rewind / resume / fork（--continue / --resume / --fork-session / /branch）。改檔前快照供 Esc 回溯（checkpoint 與 git 無關）。每個新 session 是全新 context。
擴充機制MCP（http/stdio/sse/ws）、Hooks（SessionStart / UserPromptSubmit / Pre/PostToolUse / Pre/PostCompact 等生命週期）、slashes commands、Plugins（manifest 包裝 skills/agents/hooks/MCP）。
Codex CLI OpenAI
核心 agentic loop以「一輪（turn）」為單位：prompt → 模型回應或工具呼叫（shell/patch/讀檔/MCP）→ 結果回饋 → 下一步，直到該輪結束或需使用者核准。非互動模式由 codex exec 驅動（CI/腳本）。crate 分層：core / exec / tools / protocol / app-server。
Context 管理AGENTS.md：由 ~/.codex 讀 AGENTS.override.md / AGENTS.md，再沿專案根目錄向下逐層蒐集，合併上限 32 KiB（project_doc_max_bytes）。/compact 摘要可見對話釋放 token；技能清單採 progressive disclosure（初始最多占 2% context 或 8000 字元）。
權限 / 核准模型兩層制：sandbox mode（技術邊界）× approval policy（何時問）。Sandbox：read-only / workspace-write（預設）/ danger-full-access；approval：on-request（預設）/ never。舊三模式（suggest/auto-edit/full-auto）與 untrusted 已淘汰。可設 approvals_reviewer=auto_review 由另一個 agent 先審。
Sandbox / 隔離OS 原生沙箱，預設開啟、網路預設關閉，套用於所有被 spawn 的子程序。macOS：Seatbelt；Linux/WSL2：bubblewrap (bwrap) 做檔案系統沙箱＋行程內 PR_SET_NO_NEW_PRIVS ＋ seccomp 網路過濾（Landlock 為 legacy）；Windows：Windows sandbox（新路徑 Microsoft MXC）。可寫根內 .git/.agents/.codex 強制唯讀。網路開啟後可用 features.network_proxy 做網域 allowlist。
Subagent 委派有 subagent workflow：平行 spawn 專門 agent（如 security/test/maintainability），各自獨立 agent thread，結果摘要回收主線程，對抗 context pollution。CLI 用 /agent 檢視切換。預設繼承父模型，可用 [agents] 定義不同模型。
Skills 機制SKILL.md（建構在 agentskills.io 標準上）：含 SKILL.md（必填 name+description）＋選用 scripts/references/assets。載入位置含 repo 的 .agents/skills、$HOME/.agents/skills、/etc/codex/skills。CLI 用 /skills 或 $ 觸發。
狀態持久化codex resume 重開近期對話或跨本地歷史搜尋；codex exec resume --last/--all 續跑非互動任務。Session 可 archive/delete，保留或刪除 transcript。原始碼有 rollout / history / thread-store / state 等 crate（底層格式官方未明文）。
擴充機制MCP 完整支援（STDIO + Streamable HTTP、Bearer/OAuth、server instructions），設定存 config.toml，CLI/IDE/桌面共用。Skills 可打包成 plugin（含 MCP server）。兩形態：本機（CLI/IDE/ChatGPT 桌面）與雲端（Codex Cloud 隔離容器、兩階段 runtime）。
DeepSeek Harness DeepSeek (dsh)
核心 agentic loopcore/agent-loop（ctx.agentLoop）是 Agent 介面的預設驅動器，本身也是可替換的 plugin。step = 一次模型請求＋它觸發的工具；turn = 零或多個 step。流程：turn/start → 領取輸入＋組裝 prompt/工具 schema → agent/pre-step → step/start → agent/request → 串流 → tool/call* → pre/execute/post-execute → step/end →（必要時再進 step）→ turn/end。
Context 管理專門的 compaction seam（ctx.compaction）：以 log-only 事件 compaction/start|summary|end 擴充 session event map，摘要以帶 surfaceOp:{op:'replace',startSeq,endSeq} 的 user/message 覆蓋被摺疊區段；用 log 記錄的 lock 包住（崩潰留可偵測 orphaned lock）。另有 image offload。
權限 / 核准模型ctx.approval 服務，結果 closed（allowed-once/rejected/cancelled/unavailable），fail-closed（缺 answerer 即 unavailable → 一律視為拒絕）。per-session ApprovalPolicy：ask（預設）/ never（CI）。審批以 approval/asked、approval/decided 寫入 log。Permission Preset 把 sandbox mode＋approval policy 綁成具名 preset。
Sandbox / 隔離有 ctx.sandbox seam。SandboxMode = read-only | workspace-write | danger-full-access（只管檔案效應，網路與行程可見性不在詞彙內）。dsh-sandbox-local 提供 Linux bwrap/Landlock、macOS Seatbelt、Windows ACL restricted-token 後端。Enforcement 標 full/partial（舊 Landlock ABI、Windows ACL 為 partial）。
Subagent 委派ctx.subagents 是 capability seam，多 provider 可共存（in-process / fork-in-process / acp / codex / claude-code / dsh-sdk）。子 agent 有自己 session，可傳 agentOptions、outputSchema、maxDepth、toolFilter（子 agent prompt 中該工具直接消失）、persona。支援 continuable child、send_message/interrupt_agent/list_agents。另有實驗性 Agent Teams（durable roster + task board + mailbox）。
Skills 機制ctx.skills registry，provider 可為本地檔案/packaged/remote。dsh-skill-filesystem 依 rank 掃描 root；模型端以 skill 工具載入。skill 是『optional instructions, not session events』。概念近 Anthropic Agent Skills，但是自家 registry。
狀態持久化核心設計：Session 是 SessionEvent 的 append-only 事件流，是唯一真相來源；LLM message history 是推導出來的（deriveMessages()），從不另存，replay 就是重新推導。JSONL 持久化，v0 用 session.jsonl[.zstd]、v1+ 用 session.vN.jsonl；讀取拒絕未來版本或解碼 vN→vN+1 migration chain；已提交 generation 檔永不改名/覆蓋/刪除。fork 用 buildForkSeed 在繼承前綴切點插入 session/end-seed。
擴充機制Everything is a plugin：連 model adapter、tool registry、session log、agent loop 本身都是 plugin；沒有 privileged core。組合以 profile（web/headless/sdk/sdk-minimal/acp）＋bundle＋patch 層疊構成，可用 dsh --profile web --dump-config 檢視。底層 Cordis 框架。
Gemini CLI Google
核心 agentic loopclient-server 分層：packages/cli（React/Ink 終端 UI）＋ packages/core（呼叫 Gemini API、prompt 工程、tool 註冊/編排、session 狀態）。標準 ReAct 迴圈，全程有 Hook 事件點（BeforeAgent / BeforeModel/AfterModel / BeforeTool/AfterTool / AfterAgent / PreCompress）可攔截、改寫或阻擋每一輪。
Context 管理GEMINI.md 階層式 context file：~/.gemini/GEMINI.md（全域）→ workspace 及父目錄 → JIT（工具存取某目錄時即時掃描）；支援 @file.md import；檔名可用 context.fileName 自訂（如 AGENTS.md）。有 chat history compression（近上限時自動壓縮，官方稱『資訊上無損』）。1M token context window（登入免費層）。
權限 / 核准模型mutator 工具（改檔或執行 shell）須手動批准，CLI 顯示 diff 或確切指令。MCP server 可設 trust:true 略過確認。Policy Engine：TOML 規則（toolName / argsPattern / commandPrefix）給 allow/deny/ask_user 三種決策＋priority，支援 MCP wildcard（mcp_*）。另有 trusted folders、Plan Mode。
Sandbox / 隔離支援多種後端（-s / GEMINI_SANDBOX / settings.json，優先序 flag > env > file）：macOS Seatbelt（內建六種 profile，預設 permissive-open）、Docker/Podman 容器（預設映像 ghcr.io/google/gemini-cli:latest）、Windows Native（icacls）、gVisor/runsc（Linux，需顯式）、LXC/LXD（實驗性）。另有 tool-level sandboxing 與 Sandbox Expansion 動態提權。
Subagent 委派有 subagent：主 agent 以同名 tool 委派，subagent 有獨立 context window、專屬 system prompt 與受限工具集，完成後回報 complete_task。內建：codebase_investigator、cli_help、generalist、browser_agent（預設關閉，需 Chrome 144+）。可用 @name 強制指定，或在 .gemini/agents/*.md 自訂。
Skills 機制Agent Skills（agentskills.io 標準）：有 SKILL.md。漸進式揭露：開場只注入 name/description，符合時呼叫 activate_skill（需使用者同意）才載入本體。發現層級：built-in → extension → user → workspace。
狀態持久化Checkpointing（預設關閉，只能由 settings.json 開啟；CLI flag 已於 0.11.0 移除）：批准修改檔案的 tool 後自動建快照——在 ~/.gemini/history/<project_hash> 的影子 Git repo 提交專案全貌（不動使用者自己 repo），並存對話歷史與待執行 tool call。/restore 可還原檔案＋對話並重新提議原 tool call。另有 session resume。
擴充機制MCP 完整支援（Stdio/SSE/Streamable HTTP、OAuth 2.0、trust、per-server include/exclude tools）。Extensions：打包 prompts、MCP server、custom command、theme、hooks、subagent、skills，可從 GitHub 安裝、有 gallery。免費層：Google 登入 60 req/min、1000 req/day；API key 1000/day；內建 model fallback（pro 被限流自動切 flash）。
Hermes Agent Nous Research (本機・對照)
核心 agentic looprun_conversation()：組 system prompt → while iterations < max：呼叫 LLM（OpenAI 格式 messages + tool schemas）→ 若有 tool_calls 則逐一 dispatch 後 append results 續圈 → 若純文字回應則 return。context compression 近 token 上限自動觸發。agent.max_turns 預設 90。
Context 管理context compression（compression.enabled、threshold 0.50、target_ratio 0.20）；/compress 手動壓縮。多層持久化：Memory（事實，注入每回）、context_handoff.md + session_search（上下文）、Skills（流程）、journal（推理）。toolsets 於 session 啟動載入，mid-conversation 不改（保 prompt caching）。
權限 / 核准模型approvals.mode：manual（預設，破壞性指令跳出確認）/ smart（輔助 LLM 自動核准低風險）/ off（= --yolo）。獨立於 secret redaction（security.redact_secrets 預設開，啟動時快照）。privacy.redact_pii 可雜湊 user ID。
Sandbox / 隔離terminal backend 可切 local / docker / ssh / modal / singularity / daytona；execute_code 為沙箱化 Python 執行（獨立 RPC）。⚠️ 遠端 backend 下所有 file tool 在容器內執行而非 host。另有 worktree 模式（-w / --worktree）做平行 agent 的 git 隔離。
Subagent 委派delegate_task：同步 spawn subagent，獨立 context + 獨立 terminal session，只回摘要。batch 模式平行執行（delegation.max_concurrent_children 預設 3）；role leaf（不能再委派）/ orchestrator（可再 spawn，受 max_spawn_depth 限）。⚠️ 非持久——parent 被中斷則 child 取消。長任務改用 cronjob 或 background terminal。
Skills 機制SKILL.md 技能（懶載入）：skill_view 載入完整內容；skills 目錄分 category。有 curator 背景維護技能生命週期（追蹤使用、標記過期、歸檔、絕不刪除、pin 保護）。
狀態持久化state.db（SQLite + FTS5）為 canonical session store；~/.hermes/sessions/ 存 *.jsonl transcripts 與路由索引。hermes --resume / --continue 恢復；Session 可 export JSONL / rename / delete / prune。checkpoints（可選）做檔案系統快照 /rollback。

三個最值得學的架構設計

① 沙箱與核准「解耦」——Codex CLI

把「技術上能做什麼」（OS 原生沙箱：Seatbelt / bubblewrap / MXC）與「何時要問」（approval policy）拆成兩個正交維度。低風險動作在已核可邊界內自動執行，大幅降低 approval fatigue。這是 2026 年 harness 設計最務實的一步——比單純堆 permission 規則更乾淨。關鍵細節：網路預設關閉，用 OS 原生機制而非工具層攔截，子程序一體適用。

② 狀態持久化提升為 runtime「硬性不變量」——DeepSeek Harness

官方明文：「Model-visible means logged. Every model request must be reconstructable from the log.」 Session 是 append-only 事件流、是唯一真相來源；LLM message history 是推導出來的（deriveMessages()），從不另存。結果：replay / fork / resume / telemetry / UI 全部免費繼承同一份 durable settlement，語意一致性遠勝「另外存一份 message array」。這正是本機 Hermes 四層持久化（Memory / context_handoff / Skills / journal）的架構啟發來源。

③ Context 經濟學：按需載入 + 隔離——三家共識

Claude Code / Codex / Gemini CLI 三家的 Skills 都採漸進式揭露（progressive disclosure）：session 開始只載入 SKILL.md 的 name+description（Claude Code 約 450 tokens、Codex 上限 2% context），用到才載全文。搭配 MCP schema 延後載入、subagent 以獨立 context window 執行只回摘要——這是延緩 context 爆炸的標準組合拳。

選型速查：要最強 codebase 探索選 Claude Code（但綁 Claude 模型）；要強沙箱 + 開源可換模型選 Codex CLI；要狀態可重構性 + 插件化選 DeepSeek Harness（但 developer preview）；要零成本 + MCP 一等公民選 Gemini CLI；要多平台 + provider-agnostic + durable 子系統選 Hermes。
