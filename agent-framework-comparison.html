AI Agent 框架架構比較

Maobolin Research | 2026-08-21 | 11 個框架/協議 | 基於官方 GitHub 與文件

01總覽與核心洞察

本次研究涵蓋 2026 年主流的 9 個 agent 框架與 2 個跨框架協議，依「設計架構」分成四大類。核心問題：各家的 agent 如何組織、如何協作、如何擴展？

🌐 分類地圖

💡 六大核心洞察：
① 兩大陣營成型。「終端 harness」（Claude Code、Codex、DeepSeek Harness）與「編排框架」（LangGraph、CrewAI、MAF、ADK）是當前主軸。前者把 LLM 做成可程式化的本地 agent，後者用圖形/狀態機編排多 agent 工作流。兩者解決的問題不同：harness 是「讓 agent 在真實環境幹活」，編排是「讓多個 agent 協同、可觀測、可恢復」。
② 「Skills」成為新共識。Claude Code、Codex、DeepSeek Harness、Microsoft MAF 都在引入 SKILL.md 式的技能機制（基於 Agent Skills 開放標準）。技能＝可重複使用的領域知識包，是繼「工具/MCP」之後的第二波擴展標準化。
③ MCP 是工具層事實標準，A2A 補上 agent 互通。幾乎所有框架都支援 MCP（工具/資源/脈絡存取，client-server）。A2A 則解決「不透明 agent 之間如何協作」，兩者互補——MCP 管「agent 用什麼工具」，A2A 管「agent 怎麼找別的 agent」。
④ 代際更替正在發生。Microsoft AutoGen 已進入維護模式、Semantic Kernel 已宣告「就是 MAF」，兩者由 Microsoft Agent Framework (MAF) 取代；AutoGPT Classic 已停止維護，轉型為視覺化 block builder 平台。研究框架時務必看最新繼承關係，避免採用停更項目。
⑤ 開源/閉源分野明顯。Codex（Apache-2.0）、MAF（MIT）、LangGraph（MIT）、CrewAI（MIT）、ADK（Apache-2.0）、MetaGPT（MIT）、DeepSeek Harness（MIT）開源；Claude Code 是 source-available（非 OSI 開源、綁定 Claude）；AutoGPT 平台是 Polyform Shield（限制商業託管）。
⑥ DeepSeek Harness 的獨特處。它是唯一把「狀態持久化」提升到架構級別的框架——「Model-visible ⟺ logged」原則：任何送進模型的輸入都必須能從 session log 重建，且帶版本機制。其他框架靠 checkpointing/HITL 做狀態管理，DeepSeek Harness 則把「session log 是唯一真相來源」寫進 runtime 的硬性不變量。

02終端 Harness（單 agent 執行環境）

把 LLM 包成可程式化的本地 agent，核心是「agentic loop + 工具 + 執行環境」。多 agent 皆採 subagent 委派（隔離 context window）。

DeepSeek Harness (dsh)

DeepSeek AI
MIT 開源TypeScriptdeveloper preview190k⭐
架構核心：「Everything is a plugin」——跑在 vendored 的 Cordis 上。每個能力（web/shell/fs/lsp/subagent/workflow/compaction…）都是 capability seam，採「Service Definition / Provider / Consumer」三角色。多 agent 是 subagent 委派。
關鍵特性
  • session log 唯一真相來源（Model-visible ⟺ logged + 版本機制）
  • self-modification：agent 可 inspect/mount 自己的 plugin
  • 雙 SDK（TypeScript + Python）投射同一 agent-loop
  • plan mode 作為 logged state、compaction、hooks
技術棧 / 授權
  • TypeScript（+ Python SDK），MIT
  • plugin 生態透過 dsh-plugin topic 分發
✅ 優點
  • 插件化最極致，架構一致性高
  • 狀態持久化是架構級硬性約束（非靠自覺）
  • 開源、成長最快（190k⭐，3 天前剛 release 0.1.1-rc.2）
  • 可程式化改寫自身 runtime
❌ 缺點
  • developer preview，明確標示破壞性變更
  • 生態極新、文件仍在建構
  • 以 TypeScript 為主，Python 側較輕
適用場景：想從零打造可程式化的 agent runtime、深度客製、研究 plugin 架構與狀態持久化設計。

Claude Code + Claude Agent SDK

Anthropic
非開源（source-available）Node.js143k⭐
架構核心：agentic harness——「收集上下文 → 採取行動 → 驗證結果」三階段 agentic loop。多 agent 採 subagent 模型（獨立 context window、system prompt、工具權限）。
關鍵特性
  • 五層擴展：hooks / skills / MCP / plugins / subagents
  • CLAUDE.md 記憶、checkpoints 檔案回滾、plan 模式
  • 多介面（terminal/IDE/desktop/web/Slack）
  • Agent SDK 同程序嵌入（無 IPC 開銷）
技術棧 / 授權
  • Node.js 18+，非開源（Anthropic 商業條款）
  • SDK：TypeScript + Python
✅ 優點
  • 成熟度最高、codebase 理解最強
  • 可擴展機制最豐富（五層）
  • subagent + context 管理有效對抗污染
  • 權限模型細緻（permission modes + checkpoints）
❌ 缺點
  • 非開源，深度綁定 Claude 模型
  • 需付費訂閱或 API 帳戶
  • 無 Codex 那種 OS 級 sandbox，安全靠權限審批
適用場景：個人/團隊日常編碼、codebase 探索、重構、PR、文件；用 Agent SDK 打造自訂 agent 產品。

OpenAI Codex CLI + Agents SDK

OpenAI
Apache-2.0 開源（CLI）Rust+TS117k⭐
架構核心：本地 lightweight coding agent（agentic harness）。產品分三層：Codex CLI（本地終端）、IDE extension、Codex cloud（托管容器）。多 agent 採 subagent 委派（AGENTS.md/skill 可觸發）。
關鍵特性
  • OS 級 sandbox（macOS Seatbelt / Linux bubblewrap / Windows），預設無網路
  • approval modes（read-only/auto/suggest/full-access）
  • AGENTS.md 分層指令、SKILL.md、MCP、plugins
  • codex exec 用於腳本/CI
技術棧 / 授權
  • CLI：Rust 核心 + TypeScript 重寫，Apache-2.0
  • Agents SDK：Python + TS，MIT（provider-agnostic）
✅ 優點
  • 真正開源（Apache-2.0）
  • OS 級 sandbox + 預設無網路，隔離最強
  • 輕量、快，易組合進腳本/CI
  • 與 ChatGPT 計劃整合，亦可用 API key
❌ 缺點
  • 綁定 OpenAI GPT 模型與帳戶
  • IDE extension 與 Codex cloud 非開源
  • Linux sandbox 配置（bubblewrap/AppArmor）較繁瑣
適用場景：終端/IDE 編碼、script 與 CI 自動化、需要強 sandbox 隔離的任務、ChatGPT 計劃使用者、開源專案。

03編排框架（多 agent 工作流）

用圖形/狀態機/角色編排多 agent，強調持久化、human-in-the-loop、可觀測性與生產部署。企業 prototype→production 的主力。

LangChain / LangGraph

LangChain Inc.
MIT 開源Python + JS~40k⭐
架構核心：低階圖形化狀態機。用 StateGraph 定義節點（函式/LLM 呼叫）與邊，compile 後 invoke。可在同一圖中混合「確定性手寫步驟」與「LLM 驅動的 agentic 步驟」。多 agent 靠子圖（subgraphs）組合。
關鍵特性
  • durable execution（失敗後從中斷點恢復）
  • human-in-the-loop（interrupt、狀態檢查修改）
  • checkpointing、time travel、容錯、串流
  • 短期工作記憶 + 跨 session 長期記憶
技術棧 / 授權
  • Python + JS/TS，MIT
  • MCP 經 langchain-mcp-adapters 套件
✅ 優點
  • 極細粒度控制
  • 持久化/容錯強、HITL 成熟
  • 記憶模型完備、可獨立於 LangChain 使用
  • 可上線部署
❌ 缺點
  • 低階，學習曲線陡、樣板多
  • 只做編排、無高階 agent 抽象
  • 完整除錯體驗綁 LangSmith 商業產品
適用場景：長時運行的有狀態 agent、需持久化/人機協作/可觀測的生產級複雜工作流。

CrewAI

CrewAI Inc.
MIT 開源Python~57k⭐
架構核心：兩套互補抽象——Crews（角色 role + 目標 goal + 背景 backstory 定義自主 agent 團隊，sequential/hierarchical 流程）與 Flows（事件驅動的確定性工作流，@start/@listen/@router 裝飾器）。
關鍵特性
  • 角色化 agent 協作、循序/階層流程
  • MCP 與 A2A 支援（README 明列）
  • checkpointing、human input、async
  • 結構化輸出（output_pydantic/json）、YAML 設定
技術棧 / 授權
  • Python（≥3.10，<3.14），MIT
  • UV 管理相依、企業 AMP 套件（付費）
✅ 優點
  • 高階抽象上手快
  • 角色自主 + Flow 精確控制兼備
  • 生產級模式（checkpointing/human input/結構化輸出）內建
  • 社群大
❌ 缺點
  • 主要僅 Python
  • 有遙測收集（需手動關閉）
  • 商業控制面 AMP 為付費
適用場景：多步驟工作、需角色分工的工具呼叫、結構化輸出、人工審核、自主推論 + 明確業務邏輯混用。

Microsoft Agent Framework (MAF)

Microsoft
MIT 開源.NET + Python + GoAutoGen/SK 後繼者13k⭐
架構核心：多語言 production-grade 框架。圖形化 workflow（sequential/concurrent/handoff/group collaboration），加 middleware 系統做 request/response 處理。
關鍵特性
  • checkpointing、streaming、HITL、time-travel
  • OpenTelemetry 內建觀測
  • Declarative Agents（YAML）、Agent Skills
  • Foundry Hosted Agents（2 行部署）
技術棧 / 授權
  • .NET + Python + Go，MIT
  • 多 provider（Foundry/Azure OpenAI/OpenAI/Copilot SDK）
✅ 優點
  • production-grade，跨語言（.NET/Python/Go）
  • 觀測、HITL、治理內建
  • 取代 AutoGen/SK，微軟官方主推
❌ 缺點
  • 概念多（middleware/workflow/declarative/skills）學習成本
  • 偏向 .NET / Azure / Foundry 生態
適用場景：企業生產級多 agent、微軟/Foundry/Azure 生態、需治理/觀測/安全合規的部署。

Google ADK (Agent Development Kit)

Google
Apache-2.0 開源Python（+Java/Kotlin/Go/TS）
架構核心：code-first，以 Agent（指令/工具/行為）與 Workflow（圖形化流程）組織。內建 Workflow Runtime 支援 routing、fan-out/fan-in、loops、HITL、巢狀工作流。Task API 做結構化 agent-to-agent 委派。
關鍵特性
  • code-first、model-agnostic、deployment-agnostic
  • Agent Config（無程式碼建 agent）
  • Tool Confirmation（HITL）
  • MCP 工具原生支援
技術棧 / 授權
  • 主要 Python（另有 Java/Kotlin/Go/TS），Apache-2.0
  • 可部署到 Cloud Run / Vertex AI Agent Engine
✅ 優點
  • code-first（可測試、可版本控制）
  • 圖形化工作流精準控制
  • 多語言、Google 生態深度整合、MCP 原生
❌ 缺點
  • 2.0 版有大量 breaking changes
  • 偏 Google/Gemini 生態
  • 較新，第三方社群工具成長中
適用場景：企業生產級 agent、需多 agent 協作與 HITL 的工作流、Google Cloud 部署。

04自主 Agent（目標驅動）

最早的「自主 agent」先驅，給一個目標自動拆解執行。如今 AutoGPT 轉型平台化、MetaGPT 專精軟體開發。

AutoGPT

Significant Gravitas
MIT（部分 Polyform Shield）TypeScriptClassic 已停維護
架構核心：已從「自主 agent」轉型為視覺化 block builder + agent runtime + Marketplace 平台。AutoPilot（自然語言→自動建 agent）、Agents 儀表板、Build（視覺化流程）。原版 AutoGPT Classic 已列為停止維護。
關鍵特性
  • hosted platform（付費）與 self-host（免費）雙軌
  • 45+ 第三方平台整合、上百種模型
  • 排程/觸發執行
技術棧 / 授權
  • 平台 TypeScript/Node，Polyform Shield
  • Classic（Python）與其餘 MIT
✅ 優點
  • 自然語言即可建 agent（低門檻）
  • 視覺化 builder 易用
  • 大量既有整合、社群成熟
❌ 缺點
  • Classic 停止維護且有已知漏洞
  • 平台付費、Polyform Shield 限制商業託管
  • agent 內部執行較黑箱
適用場景：商務自動化工作流、非技術使用者快速建 agent、需大量第三方 SaaS 整合。

MetaGPT

FoundationAgents
MIT 開源Python (asyncio)ICLR 2024
架構核心：Code = SOP(Team)——把標準作業程序（SOP）具體化套用到 LLM 團隊。將「軟體公司」建模為多 agent 系統（product manager / architect / project manager / engineer），輸入一行需求輸出完整 repo。核心抽象：Role、Action、Message、Environment。
關鍵特性
  • SOP 驅動的角色分工
  • generate_repo() 一行指令產出完整 repo
  • Data Interpreter（寫程式/資料分析）
  • 衍生產品 MGX（自然語言程式設計）
技術棧 / 授權
  • Python（3.9~3.11），asyncio，MIT
  • 需另裝 node/pnpm
✅ 優點
  • 結構化 SOP 使輸出可預測
  • 專精軟體開發自動化
  • 學術基礎（ICLR 2024）、MIT 開源
❌ 缺點
  • Python 版本受限（需 <3.12）
  • 偏軟體開發、通用性較低
  • 多角色多 LLM 呼叫成本高、SOP 固定彈性低
適用場景：軟體開發自動化（需求→程式碼）、資料分析（Data Interpreter）、多 agent 學術研究。

05協議層（跨框架標準）

這兩者不是框架，而是定義「工具」與「agent 之間」如何互通的開放標準。

MCP (Model Context Protocol)

Anthropic 創建 · Linux Foundation
MIT 開源語言無關
本質：「AI 應用的 USB-C 埠」——開放標準，讓 AI 應用標準化存取外部系統的資料與工具，避免每對「app × tool」各寫一次整合（build once, integrate everywhere）。
運作機制
  • client-server 架構（Host/Client/Server）
  • JSON-RPC 2.0 + 傳輸層（Stdio / Streamable HTTP + OAuth）
  • 三大 server primitive：Tools / Resources / Prompts
  • 支援 subscriptions/listen 即時通知、Tasks 長任務
與框架的關係
  • 只管「工具/資源/脈絡存取」，不管 agent 推理或協作
  • 各框架（ADK/Claude/AutoGPT…）以 MCP client 接入 MCP server
✅ 優點
  • 標準化、語言無關、開放治理
  • 動態 tool discovery、即時通知
❌ 缺點
  • 只管脈絡交換、不含 agent 邏輯，需搭配框架
適用場景：把工具/資料源連接到任何 agent 框架，統一工具存取介面。

A2A (Agent2Agent Protocol)

Google 貢獻 · Linux Foundation
Apache-2.0 開源語言無關
本質：讓「不透明（opaque）的 agentic 應用」之間互通與協作，且不必暴露內部狀態、記憶或工具。與 MCP 互補：MCP 是 agent 存取工具的協議，A2A 是 agent 之間協作的協議。
運作機制
  • JSON-RPC 2.0 over HTTP(S)
  • AgentCard（能力發現）+ Task（長期任務生命週期）
  • Message/Part/Artifact（文字/檔案/JSON）
  • 同步 request/response、SSE 串流、非同步 push
與框架的關係
  • 可把 ADK/LangGraph/BeeAI 建的 agent 包成 A2A server
  • 內建 OAuth2/APIKey/mTLS 等企業級安全
✅ 優點
  • 跨框架互通、保護 agent 不透明性（IP）
  • 支援長任務/串流/推播、企業級安全
❌ 缺點
  • 相對較新、生態成長中
  • 需 agent 主動暴露 A2A 端點
適用場景：跨公司/跨框架的 agent 協作，尤其需要保護 agent 內部 IP 的場景。

07選型建議

依「你想做什麼」快速定位。多數情境可疊加（例如 Codex 寫碼 + MCP 接工具 + LangGraph 編排生產工作流）。

你的情境推薦理由
日常編碼 / codebase 探索 / 重構Claude Code 或 Codex成熟度與 codebase 理解最強；Codex 開源 + sandbox 更安全
需要強沙箱隔離 / 寫進 CICodex CLIOS 級 sandbox、預設無網路、codex exec 易組合
企業多 agent 生產工作流（需 HITL/觀測/恢復）LangGraph 或 MAF圖形狀態機 + checkpointing；微軟/Azure 生態選 MAF，中立選 LangGraph
快速搭角色分工的多步驟任務CrewAI高階抽象上手快、結構化輸出 + 人工審核內建
Google Cloud / Vertex 部署Google ADKcode-first、Google 生態整合、MCP 原生
軟體開發自動化（需求→程式碼）MetaGPTSOP 驅動、generate_repo() 專精
從零打造可程式化 agent runtime / 研究插件架構DeepSeek Harness插件化極致、狀態持久化架構級、開源
把工具/資料接進任何框架MCP事實標準、語言無關
跨公司/跨框架 agent 協作（保護 IP）A2A不暴露內部狀態、企業級安全

📋 結論

2026 年的 agent 框架已明顯分化成兩大陣營：終端 harness（把 LLM 做成能在真實環境幹活的本地 agent）與編排框架（讓多 agent 協同、可觀測、可恢復、可上生產）。選型的第一步不是比功能，而是認清自己的問題屬於哪一類。

三個正在收斂的共識值得注意：① Skills 機制成為第二波擴展標準；② MCP 成為工具層事實標準、A2A 補上 agent 互通；③ 微軟（AutoGen/SK→MAF）與 AutoGPT（Classic→平台）都在進行代際更替，採用前務必確認項目是否仍在活躍維護。

最值得研究的獨特設計是 DeepSeek Harness 的「Model-visible ⟺ logged」——把「session log 是唯一真相來源」從最佳實踐升級為 runtime 硬性不變量。這對我們自己的 Hermes 四層持久化機制（Memory / context_handoff / Skills / journal）是最直接的架構啟發。
